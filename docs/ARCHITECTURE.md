# Архитектурные решения — этап 0

## Цель
Расширяемое ядро общего назначения. Первая поддерживаемая конфигурация:
QEMU q35, x86_64, UEFI, 256 MiB, один CPU, serial. Реальное оборудование —
отдельный будущий этап квалификации. Совместимость с Linux/POSIX не обещана.

## Модульное монолитное ядро
Память, планировщик, VFS и драйверы в будущем работают в ядре, но зависят от явных
внутренних интерфейсов. Это предварительное решение; публичный ABI не фиксируем
до ring 3 и первого пользовательского приложения. Микроядро потребовало бы раньше
решать IPC и изоляцию драйверов, что пока не является целью проекта.

## Граница доверия загрузчика
Сторонний bootloader завершает работу UEFI boot services, загружает ELF,
предоставляет карту памяти и отображение физической памяти.
Только регионы `Usable` можно выделять. Код не освобождает Bootloader/Reserved.
Региональные адреса считаются физическими; указатели получаются только через offset.
Ядро пока наследует таблицы страниц загрузчика, это не собственный VM manager.

## Владение памятью
Аллокатор выдаёт полные страницы, никогда не выдаёт адрес 0 и ничего не освобождает.
Он не Clone; состояние потреблённых страниц нельзя терять при замене аллокатора.
Два выделенных при диагностике фрейма остаются занятыми до завершения загрузки.
После этапа 0 необходимо передать этот же экземпляр/состояние PMM, а не создавать
новый аллокатор из первоначальной карты. Поддержка до 256 usable-регионов;
превышение лимита заканчивается panic. Страницы обнуляет вызывающий код.

## Unsafe и параллелизм
Unsafe сосредоточен в I/O ports, установке сегментов/TSS/IST и доступе к RAM.
Каждый блок содержит описание локальной предпосылки безопасности.
Это не доказательство корректности всего ядра: нужна отдельная ревизия перед SMP.
Сейчас ядро однопроцессорное; обработчики аппаратных IRQ ещё отсутствуют.
Логгер использует try_lock с отключением maskable interrupts и ограниченным polling;
при вложенной ошибке сообщение может потеряться, но ожидание lock не блокирует panic.
Аварийный IST-стек статический, без guard page: guard pages входят в этап VM.
IDT пока покрывает только выбранные исключения, ранние ошибки до её загрузки
не гарантируют диагностического сообщения. NMI/MCE и полный fault coverage — следующий этап.

## Зависимости и воспроизводимость
Nightly нужен для x86-interrupt ABI и сборки загрузчика. Прямые версии закреплены,
Cargo.lock должен храниться в репозитории. Обновление toolchain/зависимостей —
отдельная проверяемая задача с host tests и загрузкой QEMU. Сеть не нужна ядру,
но нужна для первоначального получения инструментов и crates.

## Дальнейшие границы модулей
`arch` предоставляет механизмы CPU; `mm` владеет PMM/VM; `sched` — жизненным циклом
задач; `syscall` проверяет пользовательские адреса; `vfs` отделяет namespace от драйверов.
Эти интерфейсы описаны как направление, соответствующих реализаций ещё нет.
